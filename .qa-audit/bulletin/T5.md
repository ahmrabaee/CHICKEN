# Bulletin — T5 (Security, Auth & Authorization)

[FOR:ALL] **CRITICAL: unauthenticated full-DB download.** `GET /v1/system/backups/:id/download` is `@Public()` and only needs a signed token, but `BACKUP_DOWNLOAD_SECRET` is unset in `.env` AND `.env.example`, so the live key is the public source constant `'fallback-secret-change-in-env'`. Anyone can forge a token and download the entire SQLite DB (all prices, costs, customers, bcrypt hashes). VERIFIED (tests/T5/backup-exfil.mjs → 35839-byte gzip). Backup ids are small integers.

[FOR:ALL] **CRITICAL: accountant/cashier can restore or import an ARBITRARY database.** Backup controller has `@Roles('admin')` but NO `@UseGuards(RolesGuard)` (RolesGuard is not global). VERIFIED: accountant `POST /system/backups/import` → 201, `download-link`/`restore`/`PUT backup/config {path_vps}` all pass. => full data takeover from the lowest role. Same guard gap: tax-template create/update/delete, reconciliation apply, credit-notes, chart-of-accounts GETs (K3-010 confirmed).

[FOR:ALL/accounting/reports] **CONFIRMED K4-009: all financial data is exposed to the accountant role at the API** (profit-loss, stock-vs-gl, expenses report, purchase supplier prices, sale `totalCost/totalProfit`, dashboard AR/AP) — UI-only gating. The `permissions` JSON (accountant lacks `reports.financial`) is never enforced; only coarse role is checked. If you test reports as a non-admin, expect to see owner-only numbers.

[FOR:ALL] **ORCH-003 CONFIRMED.** `JWT_SECRET` fallback `'default-secret-change-me'` → forged admin tokens accepted when the env var is unset. THIS build is masked because `app.module` loads `backend/.env` by absolute path (`__dirname/../.env`) regardless of cwd — so your harness `JWT_SECRET=qa-isolated-secret-<name>` is what's actually in force (you can forge an admin token for any instance with its own secret; useful for other testers who need an admin token without a login).

[FOR:ALL] **Token revocation is broken.** Logout and password-change do NOT invalidate existing ACCESS tokens (valid ≤15 min after); refresh tokens are REPLAYABLE (no rotation, reusable for 7 days). Deactivation IS enforced (access+refresh both 401 — strategy re-checks isActive each request, which also means every authenticated request does an extra user+roles+pageAccess DB read — perf note for load testers).

[FOR:UI/E2E, K4] Weak password policy (min 8, no complexity; "password"/"12345678" accepted). No login lockout/rate-limit (10 bad logins, no lock). Swagger `/api/docs(-json)` served unauthenticated in all envs. Audit log covers only login/logout/change-password + sales void + some financial ops — NOT user mgmt, backups, settings, page-access, or tax changes; IP hardcoded 'localhost'.

[FOR:ALL] **Verified SECURE (don't chase):** SQLi (Prisma parameterized), prototype pollution (whitelist), mass-assignment via `PUT /users/me`, self-privilege-escalation via user/page-access endpoints (403), setup re-run (SETUP_ALREADY_COMPLETE), request body-size limit (413), 500s don't leak stacks, CORS allowlist strict (evil origin blocked). Note CORS only allows tauri://localhost + localhost:1420/5173 — a remote BROWSER on the public domain would be CORS-blocked (remote owner access must be via the Tauri app).
