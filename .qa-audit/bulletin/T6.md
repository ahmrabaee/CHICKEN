# Bulletin — T6 (concurrency, idempotency, robustness, backup/restore, dates)

[FOR:ALL] 2026-11-25 — VERIFIED on t6: **concurrent duplicates of the same action are NOT blocked** — 5 parallel POST /sales/:id/void → 5×200 (stock restored 5×, 5 sale_void JEs: T6-003); 5 parallel /payments/sale or /sales/:id/payments → all accepted, invoice overpaid 144.00 (T6-004); 5 parallel stock adjustments → 1 qty change but 5 JEs, and adjustments overwrite concurrent sales' decrements (T6-002, lost update). If your scripts fire requests in parallel (Promise.all) expect these side effects — run sequentially for clean deltas.
[FOR:ALL] Two simultaneous POST /purchases, /expenses or /stock-transfer → 1×201 + 1×409 DUPLICATE_ENTRY (count-based numbers, T6-006). Don't parallelise creation in your own tests.
[FOR:ALL] ≥ ~20 concurrent sales → 500 DATABASE_ERROR after ~6 s (Prisma P1008/P2028; journal_mode=delete, no WAL). If you see random 500s, check whether your run was parallel (T6-001).
[FOR:T7/UI] No idempotency on POST /sales; an aborted request still commits (T6-005/T6-007) — UI double-click / retry = duplicate sale.
[FOR:ALL] Negative/zero/fractional amounts accepted by POST /purchases (weight/price/tax), /expenses (amount), /payments/sale (amount), /inventory/adjustments (unitCost): negative lots, negative-cost lots, negative expense = cash IN (T6-008). Don't be surprised by such rows if another tester's script sent them.
[FOR:T1/reports] Report day bounds are UTC (00:30 Jerusalem lands in previous day); GET /sales with endDate excludes the whole end day; GET /expenses ignores startDate/endDate (T6-010).
[FOR:security] A header-only fake SQLite archive passes /system/backups/import; restoring it bricks the server (even /auth/login 500) — combined with K3-010 any authenticated user can take the system down (T6-012). Backup files of two runs in the same second overwrite each other; retention can then delete a fresh backup (T6-011).
[FOR:ALL] Instance t6 is stopped and its DB is intentionally corrupted — do not reuse without `reset`.
