# 🛡️ الوحدة 3 — سجل المراجعة (Audit Log)

**الواجهة:** `/audit`
**الكود:** `app/frontend/src/pages/Audit.tsx` · الباك إند `app/backend/src/audit/audit.service.ts`
**الأدوار:** المدير فقط عادةً (صلاحية `audit.view`). المحاسب **لا** يملكها.

---

## 🎯 الهدف
التأكد أن سجل المراجعة يحتوي **كل حركات النظام** — كل إنشاء/تعديل/حذف/إبطال لأي كيان مالي أو مخزوني، مع **مَن** و**متى** و**ماذا تغيّر**.

> 🔎 **تنبيه مبكّر من فحص الكود:** آلية التسجيل تبدو **يدوية** (كل خدمة يجب أن تنادي `auditService.log()` بنفسها) وليست اعتراضاً تلقائياً (interceptor) لكل العمليات. هذا يعني أن أي عملية نسي مطوّرها استدعاء التسجيل فيها **لن تظهر في السجل**. سيؤكّد الـ subagent المختص مصفوفة التغطية الكاملة.

---

## 🧪 سيناريوهات الاختبار (من الواجهة)

لكل عملية تنفّذها في الوحدات الأخرى، ارجع إلى `/audit` وتأكد من ظهورها:

### A) تغطية الحركات المالية
- [ ] **بيع** (نقدي/آجل) يظهر في السجل.
- [ ] **إبطال فاتورة** يظهر مع اسم المستخدم.
- [ ] **فاتورة شراء** تظهر.
- [ ] **دفعة/تحصيل دين** تظهر.
- [ ] **مصروف** يظهر.
- [ ] **إشعار دائن / مرتجع** يظهر.
- [ ] **قيد يومية يدوي** يظهر.

### B) تغطية حركات المخزون
- [ ] **تسوية مخزون** تظهر.
- [ ] **إتلاف** يظهر.
- [ ] **نقل بين فروع** يظهر.
- [ ] **تغيير سعر صنف** يظهر (مهم محاسبياً).

### C) تغطية الإدارة والأمان
- [ ] **إنشاء/تعديل/حذف مستخدم** يظهر.
- [ ] **تغيير صلاحيات/دور** يظهر.
- [ ] **تغيير كلمة مرور** يظهر.
- [ ] **تسجيل دخول / فشل دخول** يظهر (اختياري لكنه مهم أمنياً).
- [ ] **تعديل إعدادات النظام** يظهر.
- [ ] **إنشاء/تعديل حساب في شجرة المحاسبة** يظهر.

### D) جودة بيانات السجل
لكل سطر في `/audit` تحقق أنه يحتوي:
- [ ] **المستخدم** (من نفّذ العملية) — وليس فارغاً.
- [ ] **التوقيت** الصحيح.
- [ ] **نوع الكيان + المعرّف** (entityType + entityId).
- [ ] **الإجراء** (create/update/delete/void).
- [ ] **القيمة قبل/بعد** عند التعديل (إن وُجدت) — أو على الأقل ملخص التغيير.

### E) الفلترة والبحث في الواجهة
- [ ] الفلترة حسب المستخدم تعمل.
- [ ] الفلترة حسب نوع الكيان تعمل.
- [ ] الفلترة حسب التاريخ (من/إلى) تعمل.
- [ ] الترقيم (pagination) يعمل مع سجل كبير.
