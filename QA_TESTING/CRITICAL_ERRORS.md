## 🧨 CRITICAL — تتطلب إصلاحاً قبل الاستخدام الفعلي

### C-1 🔒 قفل قاعدة البيانات + سباق المخزون (كاشيران = خطر حقيقي) — ⏳ مُصلَح جزئياً
> ✅ **تم:** WAL + busy_timeout + connection_limit=1 (مُطبَّق ومُتأكَّد — راجع DB_CONCURRENCY_LOCKING.md). ⚠️ **باقٍ:** إصلاح سباق FIFO (الجزء الثاني).

**الإجابة المباشرة على سؤالك:** **نعم، كان سيحدث "database is locked"** مع كاشيرين متزامنين (قبل الإصلاح).
- لا `busy_timeout` ولا `WAL` في [prisma.service.ts](app/backend/src/prisma/prisma.service.ts)؛ القاعدة في وضع DELETE journal؛ حوض اتصالات متعدد ⟵ الكاتب الثاني يفشل فوراً.
- **أخطر:** تخصيص FIFO يقرأ المخزون **خارج** المعاملة ([sales.service.ts:328](app/backend/src/sales/sales.service.ts#L328) → [inventory.service.ts:437](app/backend/src/inventory/inventory.service.ts#L437)) ⟵ بيعتان لنفس الصنف ⟵ **مخزون سالب وتكلفة فاسدة بلا أي رسالة خطأ**.
- توليد الأرقام `count()+1` غير ذرّي ([gl-entry.factory.ts:74](app/backend/src/accounting/gl-engine/gl-entry.factory.ts#L74)) ⟵ تصادم ⟵ **تفشل البيعة كاملة**.
- **التفاصيل والإصلاح:** [DB_CONCURRENCY_LOCKING.md](DB_CONCURRENCY_LOCKING.md). الإصلاح الأول (WAL + busy_timeout) بسيط ومنخفض المخاطر.

### C-2 📉 تسوية النقص لا تُنقِص اللوطات ⟵ انحراف دائم بين المخزون والأستاذ
[inventory.service.ts:280-311](app/backend/src/inventory/inventory.service.ts#L280). التسوية بالنقص تُحدّث الإجمالي لكن لا تُنقِص أي `inventoryLot` ⟵ بيع لاحق يخصم FIFO من بضاعة شُطبت أصلاً ⟵ **ازدواج قيد في حساب المخزون + WAC فاسد**. (هذا سبب شكوى "WAC خاطئ بعد التسوية"؛ الإصلاح السابق عالج الإجمالي فقط.)

### C-3 📦 المخزون الافتتاحي بلا قيد محاسبي
[items.service.ts:225-267](app/backend/src/items/items.service.ts#L225). يُنشئ قيمة مخزون في الجداول لكن `ItemsService` لا يُرحّل أي قيد ⟵ **حساب المخزون 1131 ناقص بقيمة كل المخزون الافتتاحي من اليوم الأول**.

### C-4 🔄 نقل المخزون بين الفروع بلا قيد ولا حفظ للقيمة
[stock-transfer.service.ts:133-360](app/backend/src/stock-transfer/stock-transfer.service.ts#L133). لا يحقن `AccountingService` ⟵ صفر قيود؛ والوجهة تزيد بتكلفة **مرسَلة من العميل** بلا تحقق ⟵ **قيمة الأصول قد ترتفع بلا مقابل**.

### C-5 🛡️ سجل المراجعة لا يسجّل معظم حركات النظام
آلية التسجيل **يدوية وغير مكتملة** (لا interceptor عام). غير مُسجَّل: **القيود اليدوية** ([accounting.service.ts:1374](app/backend/src/accounting/accounting.service.ts#L1374))، **البيع العادي والمقبوضات النقدية** ([sales.service.ts:257](app/backend/src/sales/sales.service.ts#L257))، **كل المشتريات**، **نقل المخزون**، **الإتلاف**، **المصروفات**، **تغيير الصلاحيات/الأدوار**، **تغيير الأسعار**. ⟵ لا يمكن تتبّع مَن فعل ماذا لمعظم الحركات المالية. **التفاصيل:** [03_AUDIT_LOG.md](03_AUDIT_LOG.md).

### C-6 🔓 نموذج الصلاحيات "ديكوري" + تصعيد صلاحيات فعلي
**لا يوجد guard يقرأ مصفوفة الصلاحيات إطلاقاً** — كل سلاسل `sales.void`, `debts.write_off`, ... بيانات ميتة. الحماية الفعلية الوحيدة دور خشن (admin/accountant) حيث وُصِل، وهو غير متّسق. ثغرات فعلية يستغلها **المحاسب عبر الـ API مباشرةً** (رغم إخفائها في الواجهة):
- **قوالب الضريبة (VAT):** `POST/PUT/DELETE /v1/tax/templates` بلا حارس فعّال ([tax-template.controller.ts:28](app/backend/src/accounting/tax/tax-template.controller.ts#L28)) ⟵ المحاسب يعدّل الضرائب.
- **شطب الديون:** `POST /v1/debts/:id/write-off` يسمح للمحاسب ([debts.controller.ts:96](app/backend/src/debts/debts.controller.ts#L96)).
- **تجاوز حد الخصم:** الحد يفحص `discountPct` فقط؛ المحاسب يرسل `discountAmount` ⟵ خصم غير محدود ([sales.service.ts:262](app/backend/src/sales/sales.service.ts#L262)).
- **القيود اليدوية:** المحاسب يُنشئ ويُرحّل قيوداً ([accounting.controller.ts:115](app/backend/src/accounting/accounting.controller.ts#L115)).
- **التقارير المالية** (P&L, VAT, stock-vs-GL) مكشوفة للمحاسب عبر الـ API ([reports.controller.ts:11](app/backend/src/reports/reports.controller.ts#L11)).
- **التفاصيل:** [04_PERMISSIONS_ACCOUNTANTS.md](04_PERMISSIONS_ACCOUNTANTS.md).

## 🟠 HIGH — أخطاء مالية مهمة (يُفضّل إصلاحها قريباً)

### H-1 🧾 فاتورة شراء بضريبة: تفشل أو تُسجَّل خطأ
الضريبة لا تُرحّل (1125 لا يُدين)، وشراء مدفوع بالكامل بضريبة ⟵ قيد غير متوازن ⟵ **يُرفض ⟵ لا يمكن حفظ الفاتورة** (تحت الإعداد الافتراضي). [purchases.service.ts:493](app/backend/src/purchases/purchases.service.ts#L493) + [accounting.service.ts:1108](app/backend/src/accounting/accounting.service.ts#L1108).

### H-2 💸 بيع بضريبة + خصم = قيد غير متوازن
[accounting.service.ts:276-291](app/backend/src/accounting/accounting.service.ts#L276). الإيراد يُسجّل صافي الخصم ثم يُضاف قيد خصم ⟵ اختلال بمقدار الخصم ⟵ قد يُرفض البيع.

### H-3 🔢 توليد أرقام غير ذرّي يُفشل البيعة (مرتبط بـ C-1)
تصادم رقم القيد/الدفعة/اللوط ⟵ P2002 ⟵ تراجع المعاملة. رقم البيع وحده محميّ.

### H-4 🗑️ الإتلاف بلا SLE ويتجاهل حساب الفرع
[wastage.service.ts:47](app/backend/src/wastage/wastage.service.ts#L47). دفتر المخزون لا يعكس الإتلاف، والقيد يُدين المخزون الافتراضي 1131 بلا حساب الفرع.

### H-5 🧮 الضريبة تختفي في الإيراد عند الإعداد الافتراضي
مع `tax_engine_enabled=false` (الافتراضي) وقالب ضريبي مفعّل ⟵ VAT تُدمج في الإيراد 4110 و**2120 لا يُدان** ⟵ إيراد مبالغ والتزام ضريبي مفقود. [sales.service.ts:366](app/backend/src/sales/sales.service.ts#L366).
