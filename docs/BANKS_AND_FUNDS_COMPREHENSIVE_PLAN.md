# خطة شاملة: البنوك والصناديق — المشتريات، المدفوعات، والرصيد

**تاريخ الإعداد:** 2026-03-18  
**الإصدار:** 1.0

---

## 1. الملخص التنفيذي

هذه الخطة تغطي:
1. **المشتريات** — إضافة اختيار طريقة الدفع (نقدي / تحويل بنكي / بطاقة) واختيار البنك عند الدفع بالتحويل البنكي
2. **المدفوعات** — التحقق من ظهور قائمة البنك عند اختيار "تحويل بنكي" وإظهارها أيضاً عند "بطاقة"
3. **القوانين المحاسبية** — التأكد من توازن القيود (الدائن = المدين) والتحقق من الرصيد قبل تنفيذ العمليات
4. **فحص الرصيد** — كيفية معرفة رصيد البنك أو الصندوق في النظام

## 2. الوضع الحالي — ما هو موجود وما ينقص

### 2.1 المشتريات (`/purchasing/new`)

| العنصر | الحالة | التفاصيل |
|--------|--------|----------|
| Backend: `paymentMethod`, `bankAccountId` | ✅ | `purchases.service.ts` يقبل ويستخدمهما في `createPurchaseJournalEntry` |
| المحاسبة: قيد على البنك | ✅ | `getPurchaseGLMap` و `resolveCashOrBankAccount` توجه المبلغ إلى الصندوق أو البنك |
| Frontend: طريقة الدفع | ❌ | النموذج لا يحتوي على `paymentMethod` ولا `bankAccountId` |
| النتيجة | 🔴 | كل المدفوعات تُسجّل افتراضياً في الصندوق (1111) لأن الواجهة لا ترسل طريقة الدفع ولا البنك |

### 2.2 المدفوعات (`/payments/new`)

| العنصر | الحالة | التفاصيل |
|--------|--------|----------|
| قائمة البنك عند "تحويل بنكي" | ⚠️ جزئي | تظهر فقط إذا `bankAccounts.length > 0` — أي يجب إضافة حسابات بنكية من الإعدادات أولاً |
| قائمة البنك عند "بطاقة" | ❌ | الكود الحالي يعرض البنك فقط لـ `bank_transfer`، وليس لـ `card` |
| إجبارية البنك | ⚠️ | عند اختيار تحويل بنكي بدون بنوك مُعدّة، لا تظهر رسالة توجيهية واضحة |

### 2.3 القوانين المحاسبية

| العنصر | الحالة | التفاصيل |
|--------|--------|----------|
| توازن القيد (الدائن = المدين) | ✅ | `createJournalEntryInternal` و `gl-validator` يتحققان من التساوي |
| التحقق من الرصيد قبل الدفع | ❌ | لا يوجد تحقق من أن الصندوق/البنك يكفي قبل تنفيذ العملية |
| رسالة "رصيد غير كافٍ" | ❌ | غير مدمجة في أي من الخدمات |

### 2.4 فحص الرصيد

| الطريقة | الملف | الوصف |
|---------|-------|-------|
| ميزان المراجعة | `GET /accounting/trial-balance?asOfDate=YYYY-MM-DD` | يُرجع كل الحسابات مع `debit`, `credit`, `balance` |
| دفتر الحساب | `GET /accounting/ledger/:accountCode?startDate=...&endDate=...` | يُرجع حركات الحساب مع الرصيد الجاري |
| صفحة المحاسبة | `/accounting` | تعرض ميزان المراجعة وكشوف الحسابات |

**آلية الحساب:**
- للحسابات من نوع أصل (مثل الصندوق 1111 والبنوك 1112-xxx): **الرصيد = المدين − الدائن**
- الرصيد الجاري = مجموع الحركات السابقة حتى تاريخ معين
- القيود المعتمدة فقط (`isPosted: true`) تُحتسب في ميزان المراجعة

## 3. خطة التنفيذ التفصيلية

### المرحلة 1: المشتريات — إضافة طريقة الدفع والبنك

#### 1.1 Frontend: `PurchaseProfile.tsx`

**الإضافات المطلوبة:**
- حقل `paymentMethod` في schema مع القيم: `cash`, `card`, `bank_transfer`, `mobile_payment`, `check`
- حقل `bankAccountId` (اختياري)
- عرض قائمة البنوك فقط عند `paymentMethod === 'bank_transfer'` أو `paymentMethod === 'card'` ووجود حسابات بنكية
- جلب `bankAccounts` عبر `useQuery` + `bankAccountsService.getAll()`

**موقع الحقول:**
- إدراج حقل "طريقة الدفع" بجانب "المبلغ المدفوع" في قسم الدفع
- عند اختيار تحويل بنكي أو بطاقة: إظهار قائمة منسدلة "الحساب البنكي"

**ملاحظة:** الـ Backend يدعم هذه الحقول بالفعل، لذلك يكفي تحديث الـ DTO المرسل:
```typescript
// في CreatePurchaseDto
paymentMethod?: string;  // 'cash' | 'card' | 'bank_transfer' | ...
bankAccountId?: number;
```

#### 1.2 DTO: `CreatePurchaseDto`

التأكد من إضافة `paymentMethod` و `bankAccountId` في `app/frontend/src/types/purchases.ts` إن لم يكونا موجودين.

### المرحلة 2: المدفوعات — تحسين عرض البنك

#### 2.1 توسيع شروط إظهار قائمة البنك

**التعديل في `PaymentProfile.tsx`:**
```tsx
// الحالي:
{paymentMethod === "bank_transfer" && bankAccounts.length > 0 && (...)}

// المقترح:
{(paymentMethod === "bank_transfer" || paymentMethod === "card") && bankAccounts.length > 0 && (...)}
```

#### 2.2 رسالة توجيهية عند عدم وجود بنوك

عند اختيار "تحويل بنكي" أو "بطاقة" ولا يوجد حسابات بنكية:
- إظهار تنبيه: "يجب إضافة حسابات بنكية من الإعدادات أولاً"
- رابط إلى `/settings` → تبويب الحسابات البنكية

#### 2.3 إجبارية البنك عند التحويل البنكي

- عند `paymentMethod === 'bank_transfer'` و `bankAccounts.length > 0`: جعل `bankAccountId` إجبارياً في التحقق
- رسالة: "يجب اختيار البنك عند الدفع بالتحويل البنكي"

### المرحلة 3: التحقق من الرصيد (الدائن = المدين + رصيد كافٍ)

#### 3.1 إضافة دالة التحقق من الرصيد

**في `AccountingService` أو خدمة جديدة:**
```typescript
async getAccountBalance(
  accountIdOrCode: number | string,
  asOfDate?: Date,
  tx?: any
): Promise<number>
```
- تجميع `journalEntryLine` للحساب المعين حتى `asOfDate`
- الرصيد = مجموع (مدين − دائن)
- للأصول: رصيد موجب = مدين (نقد متوفر)

#### 3.2 دالة مساعدة: رصيد الصندوق أو البنك

```typescript
async getCashOrBankBalance(
  paymentMethod: string,
  bankAccountId?: number | null,
  asOfDate?: Date,
  tx?: any
): Promise<{ accountId: number; balance: number }>
```
- تحدد الحساب عبر `resolveCashOrBankAccount`
- تحسب الرصيد حتى التاريخ المحدد
- تُستخدم قبل تنفيذ أي عملية دفع/صرف من الصندوق أو البنك

#### 3.3 التحقق قبل إنشاء القيد

**نقاط التطبيق:**
1. **المشتريات** — عند `amountPaid > 0`: التحقق من رصيد الحساب (صندوق أو بنك) قبل إنشاء القيد
2. **المدفوعات** — قبل `createPaymentReceivedJournalEntry` أو `createPaymentMadeJournalEntry`: التحقق من الرصيد
3. **المصروفات** — عند الدفع النقدي أو البنكي: التحقق من الرصيد
4. **نقطة البيع** — عند إتمام البيع النقدي/بطاقة/تحويل: التحقق من الرصيد (للاستلام في البنك، الرصيد يزيد؛ التحقق هنا غير مطلوب للاستلام، بل للصرف فقط)

**ملاحظة:** عمليات **الاستلام** (مثل تحصيل من عميل أو بيع نقدي) تزيد رصيد الصندوق/البنك، ولا تحتاج تحققاً من الرصيد السابق.  
عمليات **الصرف** (شراء، دفعة لمورد، مصروف) تحتاج التحقق.

#### 3.4 رسالة الخطأ عند عدم كفاية الرصيد

```typescript
throw new BadRequestException({
  code: 'INSUFFICIENT_BALANCE',
  message: `Insufficient balance in ${accountName}. Available: ${fmt(balance)} ₪, required: ${fmt(amount)} ₪`,
  messageAr: `الرصيد غير كافٍ في ${accountNameAr}. المتاح: ${fmt(balance)} ₪، المطلوب: ${fmt(amount)} ₪`,
});
```

### المرحلة 4: فحص الرصيد — كيف يعمل في النظام

#### 4.1 API الحالية

| API | الاستخدام |
|-----|-----------|
| `GET /accounting/trial-balance?asOfDate=YYYY-MM-DD` | جلب كل الحسابات ورصيدها حتى تاريخ معين |
| `GET /accounting/ledger/:accountCode?startDate=...&endDate=...` | دفتر حساب معين مع الرصيد الجاري |

#### 4.2 رصيد الصندوق (1111)

```
الرصيد = مجموع (مدين − دائن) لكل JournalEntryLine لحساب 1111
```
- الحركات المعتمدة فقط (`isPosted: true`) تُحتسب
- إن كان النظام يستخدم GL Engine، تُستخدم الحركات من `GLPosting` أو ما يعادلها

#### 4.3 رصيد البنك (مثل 1112-001)

كل حساب بنكي مرتبط بـ `BankAccount.accountId` (حساب في دليل الحسابات).
```
الرصيد = مجموع (مدين − دائن) لكل JournalEntryLine لحساب البنك المعين
```

#### 4.4 واجهة المستخدم لفحص الرصيد

- **المحاسبة → ميزان المراجعة:** يعرض كل الحسابات ورصيدها
- **المحاسبة → كشف حساب:** اختيار الحساب (مثل 1111 أو كود البنك) لعرض الحركات والرصيد

**تحسين مقترح (اختياري):**
- صفحة "أرصدة سريعة" تعرض:
  - رصيد الصندوق (1111)
  - رصيد كل بنك مُعد
- أو بطاقة في لوحة التحكم تعرض المجموع النقدي (صندوق + بنوك)

## 5. ملخص القوانين المحاسبية المطبقة

1. **توازن القيد:** كل قيد يحقق: مجموع المدين = مجموع الدائن ✅ (موجود)
2. **التحقق من الرصيد:** قبل أي صرف من الصندوق أو البنك، التحقق من كفاية الرصيد ⏳ (مطلوب إضافته)
3. **تحديد وجهة الدفع/الاستلام:** 
   - نقدي بدون بنك → حساب 1111 (الصندوق)
   - تحويل بنكي أو بطاقة + بنك محدد → حساب البنك (من `BankAccount.accountId`)

## 7. سيناريوهات اختبار مقترحة

1. إنشاء مشتريات جديدة بدفع تحويل بنكي + بنك محدد → التحقق من القيد في حساب البنك وليس الصندوق
2. إنشاء دفعة جديدة بتحويل بنكي + اختيار بنك → التحقق من ظهور البنك وإرساله للـ API
3. محاولة دفع مبلغ يتجاوز رصيد البنك → ظهور رسالة "الرصيد غير كافٍ"
4. فتح ميزان المراجعة → التحقق من ظهور رصيد الصندوق ورصيد البنوك بشكل صحيح
