# سيناريو اختبار صفحة ميزان المراجعة (Trial Balance)

## 1. ما هي صفحة ميزان المراجعة؟

صفحة **ميزان المراجعة** (Trial Balance) تقرير محاسبي أساسي يجمع أرصدة جميع الحسابات في دليل الحسابات. تُستمد البيانات من القيود اليومية **المرحّلة** فقط (`isPosted: true`).

### الأهداف الرئيسية
- إثبات **المساواة الرياضية** لنظام القيد المزدوج: إجمالي المدين = إجمالي الدائن
- عرض أرصدة الحسابات (مدين/دائن) في نقطة زمنية محددة
- التحقق من سلامة القيود قبل إعداد القوائم المالية (قائمة المركز المالي، قائمة الدخل)

### المصدر التقني
- **API:** `GET /v1/accounting/trial-balance?asOfDate=YYYY-MM-DD` (اختياري)
- **مصدر البيانات:** جدول `journal_entry_lines` مرتبط بـ `journal_entry` حيث `isPosted = true`

## 2. صحة البيانات في ميزان المراجعة

### 2.1 معيار الصحة الأساسي
| المعيار | الشرط | التفسير |
|--------|-------|---------|
| **التوازن** | إجمالي المدين = إجمالي الدائن | في نظام القيد المزدوج، كل قيد مدين له مقابل دائن. المجموع الكلي يجب أن يكون متساوياً. |
| **وحدات التخزين** | المبالغ تُخزَّن بالـ agorot (÷ 100 للعرض) | 292.00 ₪ يُخزَّن كـ 29200 |
| **القيود المعتمدة** | تُحسب فقط القيود المرحّلة | القيود المسودة لا تُضمَّن في ميزان المراجعة |

### 2.2 منطق الباكند (`accounting.service.ts`)
```
1. groupBy accountId من journal_entry_lines
2. فلترة: journalEntry.isPosted = true
3. فلترة اختيارية: entryDate <= asOfDate (إن وُجد)
4. _sum: debitAmount, creditAmount لكل حساب
5. JOIN مع accounts لجلب code, name, accountType
6. إرجاع: accountCode, accountName, accountType, debit, credit
```

### 2.3 متى يكون الميزان صحيحاً؟
| الحالة | المعنى |
|--------|--------|
| **إجمالي المدين = إجمالي الدائن** | الميزان متوازن رياضياً ✓ |
| **إجمالي المدين ≠ إجمالي الدائن** | خطأ في القيود أو في منطق الترحيل — يظهر تنبيه أحمر في الواجهة |

> **ملاحظة:** التوازن الرياضي لا يضمن صحة الرصيد الفعلي لكل حساب. التحقق من صحة الأرصدة يتطلب مراجعة القيود ودفاتر الحساب.

## 4. اختبارات التحقق (Validation)

### 4.1 التحقق من صيغة البيانات
| # | الحالة | الوصف | النتيجة |
|---|--------|-------|---------|
| V-01 | ☐ | كل صف له: accountId, accountCode, accountName, accountType, debit, credit | أنواع البيانات صحيحة |
| V-02 | ☐ | debit و credit أرقام غير سالبة (>= 0) | لا توجد قيم سالبة في الأعمدة |
| V-03 | ☐ | مجموع المدين = مجموع الدائن (عند صحة النظام) | المساواة محققة |

### 4.2 التحقق من الحساب
```
totalDebit = Σ(debit) لكل صف
totalCredit = Σ(credit) لكل صف
isBalanced = (totalDebit === totalCredit)
```

| # | الحالة | الاختبار | النتيجة |
|---|--------|---------|---------|
| V-04 | ☐ | تشغيل الحساب يدوياً على نفس بيانات API والمقارنة مع الواجهة | الأرقام متطابقة |
| V-05 | ☐ | عند إضافة قيد غير متوازن (مدين ≠ دائن) وترحيله: التحقق من ظهور تنبيه عدم التوازن | يكتشف الخطأ |

### 4.3 حدود وأخطاء
| # | الحالة | الإجراء | النتيجة المتوقعة |
|---|--------|---------|-------------------|
| V-06 | ☐ | قطع الاتصال بالإنترنت ثم فتح ميزان المراجعة | رسالة خطأ مناسبة أو retry |
| V-07 | ☐ | استجابة API فارغة `[]` | عرض "لا توجد بيانات" |

## 6. ملخص الحالات والنتائج

| الحالة | المعيار | النتيجة |
|--------|--------|---------|
| **متوازن** | totalDebit === totalCredit | صف إجمالي عادي، لا تنبيه |
| **غير متوازن** | totalDebit !== totalCredit | تنبيه أحمر + تمييز صف الإجمالي |
| **فارغ** | trialBalance.length === 0 | "لا توجد بيانات" |
| **تحميل** | trialLoading === true | مؤشر تحميل |
