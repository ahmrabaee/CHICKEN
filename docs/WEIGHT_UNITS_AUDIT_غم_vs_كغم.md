# تدقيق وحدات الوزن: غم vs كغم

## الهدف
استكشاف شامل للنظام لتحديد جميع المواقع التي تعرض **غم** (غرام) أو **غ** بينما يفترض أن تُعرض القيم بوحدة **كغم** (كيلوغرام) حسب منطق النظام.

---

## ملخص النظام
- **التخزين الداخلي:** جميع الأوزان تُخزَّن بالغرام (`weightGrams`, `currentQuantityGrams`, إلخ)
- **العرض للمستخدم:** يُفترض أن يعرض بالكيلوغرام (كغم) لأن الأسعار مُعرّفة «لكل كغم»
- **الرموز:** `غ` = غرام، `كغم` أو `كجم` = كيلوغرام

## 3. دوال التنسيق (Format)

### 3.1 `pdf.helpers.ts` (Backend)
```typescript
export function formatWeight(amount: number | string): string {
    return Number(amount).toFixed(3) + ' kg';
}
```
**ملاحظة:** المعامل `amount` — التحقق من السياق: إن كان يُمرَّر بالغرام يجب تحويله أولاً إلى كغم. في قوالب الفواتير غالباً يُمرَّر `quantity` = weightGrams/1000 (كغم) لذا قد يكون صحيحاً.

---

### 3.2 `lib/db.ts` (Backend)
```typescript
export function formatWeight(grams: number): string {
  const kg = toKilograms(grams);
  return `${kg.toFixed(3)} كجم`;
}
```
✓ صحيح — يستقبل غرام ويعرض كغم.

---

### 3.3 `common/utils/helpers.ts` (Backend)
```typescript
export function formatWeight(grams: number, locale = 'ar-SA'): string {
  const kg = toKilograms(grams);
  return `${...format(kg)} كغ`;
}
```
✓ صحيح.

## 6. توصيات

1. **توحيد العرض:** اعتماد **كغم** كوحدة عرض افتراضية في الواجهة، والاحتفاظ بالغرام للتخزين والـ API فقط.
2. **دالة مشتركة:** استخدام دوال مثل `formatWeightGramsToKg(grams)` في الفرونتند لتوحيد العرض.
3. **التقارير:** التأكد أن الـ API يرجع الأوزان بالغرام، والفرونتند يحوّلها إلى كغم عند العرض.
4. **الباركود:** الإبقاء على "غرام" في إعدادات الباركود لأن المعيار التقني يعتمد الغرام.
